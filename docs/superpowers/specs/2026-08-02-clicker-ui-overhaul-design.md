# Clicker 主界面与设置窗口重设计

## 目标

重做 Clicker 的界面层级和视觉语言，解决现有界面中主操作按钮过大、侧栏比例失衡、系统蓝色选中态突兀、动作卡片臃肿、设置形态像表单弹窗，以及缺少标准 `Command-,` 设置入口的问题。

本次只重构呈现层和设置窗口入口。录制、回放、重复、时间轴、持久化、快捷键校验和权限业务行为保持不变。

## 设计方向

主窗口采用已确认的组合方向：以 Editorial Utility 为整体结构，使用紧凑脚本控制区。界面应表现为成熟、克制、内容优先的 macOS 生产力工具，而不是 SwiftUI 默认控件的直接堆叠。

设置窗口采用独立原生 Settings 结构；外观设置使用紧凑分组行，快捷键录入保留整块可点击的录入卡。

## 主窗口

### 窗口框架

- 保留双栏结构，左侧为脚本库，右侧为脚本详情。
- 侧栏理想宽度为 230pt，并允许在合理范围内适配窗口宽度。
- 右侧从上到下依次为紧凑控制区、动作列表和固定的添加动作入口。
- 760×480 最小窗口尺寸下，脚本标题、录制、回放、重复设置、设置入口和动作列表均保持可达。

### 标题栏与设置入口

- 窗口标题继续显示 Clicker。
- 设置入口仅显示右上角齿轮图标，不显示“设置”文字或快捷键提示。
- 齿轮保留 tooltip、键盘焦点和 VoiceOver 标签。
- 齿轮与应用菜单中的“设置…”打开同一个独立 Settings 窗口。
- 应用菜单使用标准 `Command-,` 快捷键。
- 重复打开设置时聚焦现有窗口，不创建多个设置窗口。

### 侧栏

- 顶部保留 Clicker 标志和名称，下方显示“脚本库”和脚本数量。
- 脚本行显示名称以及“动作数 · 预计时长”元数据。
- 选中态使用中性暖灰底色，不使用系统蓝色，也不使用录制红色铺底。
- 侧栏不使用大面积卡片或阴影。
- 保留脚本重命名、复制和删除上下文菜单。

### 紧凑脚本控制区

- 控制区高度目标约 96–104pt。
- 左侧显示脚本名称及“动作数 · 预计时长”。
- 录制和回放位于同一行、同一层级，目标高度为 38pt，宽度随标签适配而非占据大块固定区域。
- 录制按钮使用白底、红字和红色描边；回放按钮使用炭黑底和白字。
- 按钮运行时原位切换为对应停止状态，不改变控制区尺寸。
- 重复次数、无限重复和间隔位于同一紧凑行，使用短标签、紧凑输入框和明确单位。
- 播放轮次信息在参数区附近显示，但不挤掉主操作或改变控制区高度。
- 禁用状态保留文字可读性，并使用系统 disabled 语义。

### 动作列表

- 移除每个动作外围的大圆角描边卡片。
- 每个动作使用紧凑分隔行：左侧为统一尺寸的 SF Symbol，中间为名称和摘要，右侧为持续时间。
- 行间依靠分隔线、间距和轻微状态底色建立层级。
- 双击编辑、拖动排序、复制、删除和上下文菜单行为保持不变。
- 当前回放动作只显示左侧红色活动轨迹或静态强调，不改变行高、文本位置或列表布局。
- 系统启用“减少动态效果”时不播放呼吸动画。
- 添加动作入口固定在内容底部，使用次要层级，不与录制或回放竞争。

## 设置窗口

### 窗口行为

- 将当前设置 sheet 迁移为 SwiftUI `Settings` scene。
- 设置独立于主窗口显示，符合 macOS 标准设置窗口行为。
- 所有设置即时保存，不显示“完成”按钮。
- “恢复默认设置”保留为低权重操作。
- 录制或回放开始时不强制关闭设置窗口；不可编辑项目使用明确 disabled 状态，避免窗口突然消失。

### 外观设置

- 外观放在“通用”分组行。
- 提供“系统、浅色、深色”三个选项；底层继续映射现有 `AppAppearancePreference`。
- 选择后即时更新应用外观并持久化。

### 快捷键录入

- 快捷键放在“录制”分组内。
- 使用整块可点击的紧凑录入卡，展示标题、用途、当前组合键键帽和重新录入提示。
- 点击卡片后原位进入捕获状态，提示替换为“请按下新的组合键…”，不改变卡片或窗口尺寸。
- 捕获成功后即时持久化并退出监听。
- 冲突、仅修饰键和裸文本键继续使用现有校验规则。
- 校验消息显示在卡片附近，不改变其他设置行的位置。
- 继续使用本地 first responder 捕获，不注册临时全局监听。

## 视觉系统

### 色彩

- 移除所有由系统 accent 自动带入的蓝色选中态和蓝色按钮状态。
- 浅色窗口使用中性灰白，不再用偏黄米色铺满整个界面。
- 深色窗口使用中性炭黑，不使用纯黑或蓝灰。
- 红色只用于录制、停止录制、危险操作、活动轨迹和错误语义。
- 普通选择、焦点和回放使用中性色；颜色不是表达状态的唯一手段。
- 浅色与深色分别解析语义 token，保证文字、图标、边界和禁用状态的可读性。

### 排版、尺寸与形状

- 使用 macOS 系统字体和语义字号，不引入第三方字体。
- 采用 4pt/8pt 间距节奏，主要层级使用 8、12、16、24pt 间距。
- 普通控件圆角限制在 6–10pt。
- 阴影仅用于真正悬浮的窗口或弹层。
- SF Symbols 使用一致的笔画粗细；同一层级不混用实心和描边风格。
- 可点击区域保持至少 32pt，并为小图标扩展命中区域；主要控件目标高度为 38pt。

### 状态与可访问性

- 所有交互保留清晰的 hover、pressed、disabled 和键盘焦点状态。
- 设置齿轮、录制、回放、动作菜单和快捷键卡均提供准确的 accessibility label 和必要 help。
- 状态同时通过文字、形状或图标表达，不只依赖颜色。
- 尊重“减少动态效果”和系统辅助文字设置。

## 其他界面

- 权限页、空脚本库、未选择脚本、空动作列表和动作编辑窗口复用同一套颜色、间距、图标和按钮 token。
- 权限请求、重新检测、编辑保存和取消的行为不变。
- 持久化和快捷键注册错误继续使用系统 alert。
- 删除继续使用系统 destructive 语义，不新增自绘确认弹窗。

## 组件与边界

呈现层拆分为职责明确的组件：

- 主窗口标题栏设置入口。
- 脚本侧栏标题和脚本行。
- 紧凑脚本控制区。
- 重复与间隔参数条。
- 动作列表行和活动轨迹。
- Settings 根视图、外观设置行和快捷键录入卡。

集中式视觉 token 统一管理颜色、间距、圆角、控件高度、分隔线和状态强调。不得为单个页面继续增加无来源的临时颜色或尺寸。

不重构 `AppState` 的业务状态、不修改录制或回放引擎、不改变脚本数据模型。所有 Swift 文件继续少于 800 行。

## 数据流与错误处理

- 主窗口组件继续读取现有 `AppState`，所有操作沿用现有状态方法和通知通道。
- Settings scene 与主窗口共享同一个 `AppState` 实例。
- 外观和停止快捷键修改后立即写入现有注入式 store。
- 快捷键候选先通过现有校验，再更新 state 和 store；失败候选不得覆盖当前值。
- 持久化、权限和快捷键注册错误继续通过现有结构化状态展示。

## 测试策略

严格执行 RED、GREEN、REFACTOR。每个行为先新增或修改测试，并运行确认测试因目标行为缺失而失败，之后才修改生产代码。

自动测试至少覆盖：

- App 声明标准 Settings scene 和 `Command-,` 设置命令。
- 齿轮图标打开同一个设置窗口，且不渲染“设置”文字或快捷键提示。
- 主控制区的录制与回放尺寸、层级和运行状态保持稳定。
- 语义 token 不再把普通选择解析为系统蓝色。
- 侧栏、控制区、动作行和设置窗口在浅色与深色下正确渲染。
- 760×480 视口中核心控件可见且命中区域有效。
- 动作列表不再使用逐项大描边卡片，活动状态不改变布局。
- Settings 中外观选择即时更新并持久化。
- 快捷键录入卡捕获前后尺寸稳定，并继续使用本地 first responder。
- 现有快捷键冲突校验、录制、回放、编辑和持久化测试无回归。

最终自动验证包括：

- 完整 `swift test`。
- Debug 和 Release 构建。
- 所有 Swift 文件少于 800 行。
- `git diff --check`。
- 重新构建应用 bundle，校验 Info.plist、图标资源和代码签名。
- 主窗口和设置窗口的浅色、深色截图检查。

人工验收单独记录，不以自动测试替代：

- 菜单栏 `Command-,` 打开并聚焦 Settings 窗口。
- 齿轮设置入口和真实键盘焦点。
- 浅色、深色和跟随系统的实时观感。
- VoiceOver 顺序与标签。
- 最大辅助文字字号和减少动态效果。
- 真实录制、倒计时、停止、回放和长脚本滚动。

## 工程约束

- Swift 5.9、SwiftUI、AppKit，macOS 14+。
- 不引入第三方依赖或第三方字体。
- 不修改 TCC、`.netrc` 或 Git identity。
- 不执行任何远程 Git 操作。
- `.omc/` 和 `docs/superpowers/clicker-handoff.md` 保持未跟踪且不暂存。
- 临时视觉 mockup 不进入提交，设计阶段结束后清理。
- 测试不得投递真实键鼠输入、修改系统权限或真实切换外部应用。
- 使用 Conventional Commits，并精确暂存本任务文件。
