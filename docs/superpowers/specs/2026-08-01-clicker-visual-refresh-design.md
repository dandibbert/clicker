# Clicker 图标与界面视觉刷新设计

## 目标

为 Clicker 建立完整、统一且适合长期使用的 macOS 视觉系统，解决当前没有应用图标、界面层级薄弱、录制与回放主次不一致的问题。

本次刷新覆盖应用图标、主窗口、权限引导、空状态、录制设置及运行状态反馈。录制、回放、持久化、权限和脚本编辑的业务行为保持不变。

## 品牌方向

### 应用图标

正式图标采用已确认的「Cursor Trail」方向：

- macOS 标准圆角方形轮廓。
- 暖白色底面。
- 黑色鼠标指针作为主体。
- 一段克制的红色运动轨迹与端点，表达鼠标操作被捕捉并继续执行。
- 不使用文字，不直接拼贴录制圆点和播放三角形。
- 在 16×16、32×32 等 Dock/Finder 小尺寸下仍能辨认主体轮廓。
- 图标源文件保留为可维护的矢量资产，并生成标准 `.icns` 资源。

构建后的 `Clicker.app` 必须在 `Info.plist` 声明图标资源，使 Finder、Dock、应用切换器和系统信息面板使用正式图标。

### 色彩与外观

界面跟随 macOS 系统浅色/深色外观：

- 浅色：暖白表面、炭黑文字、中性暖灰分隔、克制红色强调。
- 深色：炭黑表面、暖白文字、深暖灰层级、同一红色强调。
- 红色只用于录制、危险操作、活动轨迹和关键状态，不作为大面积背景。
- 回放使用高对比中性主操作样式，视觉权重与录制一致，但不复用录制红色语义。
- 颜色必须使用语义化动态色或 SwiftUI 环境色，不能以固定浅色值强行覆盖深色模式。

排版沿用 macOS 系统字体和 Dynamic Type 语义层级，不引入第三方字体。

## 主窗口结构

主窗口采用已确认的「Refined Split」结构，保留当前左右分栏的使用模型：

1. 左侧为脚本库。
2. 右侧为当前脚本详情。
3. 录制与回放集中在右侧顶部主操作区。
4. 参数设置位于标题与动作列表之间。
5. 动作列表占据主要内容空间。
6. 添加动作入口固定在列表底部，视觉权重低于录制与回放。

界面密度采用“适中舒展”：比当前界面拥有更明确的留白、卡片边界和层级，但不能为了装饰显著减少长脚本的可见动作数量。

### 左侧脚本库

侧边栏包含：

- Clicker 品牌标识与名称。
- “脚本库”标题及脚本数量。
- 脚本列表。
- 统一空状态。

脚本行显示：

- 脚本名称。
- 动作数量。
- 最近修改信息，使用次要文本样式。
- 清晰但克制的选中态。

现有重命名、复制和删除上下文菜单保持可用。空列表时显示正式品牌语气的说明与“开始录制”主入口。

### 脚本标题与主操作区

右侧顶部标题区显示：

- 脚本名称。
- 动作数量。
- 可由现有时间轴数据安全计算时显示预计时长。

录制和回放位于同一容器、同一视觉层级：

- 按钮高度、字号和主要占位相同。
- 录制使用红色录制语义。
- 回放使用中性高对比主操作语义。
- 录制中或倒计时中，录制按钮切换为明确的“停止录制”。
- 回放中，回放按钮切换为明确的“停止回放”。
- 禁用状态必须同时依靠对比度、文字和系统 disabled 语义，不只依赖颜色。

录制与回放不能继续分散在不同工具栏层级，也不能让其中一个成为另一个的附属操作。

### 参数条

重复次数、无限重复和回放间隔组合为紧凑参数条：

- 保留现有字段和行为。
- 使用明确标签与单位。
- 编辑禁用状态与应用阶段一致。
- 不增加折叠面板或高级设置层级。

### 动作列表

每个动作使用统一卡片结构：

- 左侧：动作类型图标。
- 中间：动作名称与关键摘要。
- 右侧：持续时间或相关次要值。
- 双击编辑、拖动排序、上下文菜单、删除与复制行为保持不变。

回放当前动作时：

- 使用红色活动轨迹或边缘强调。
- 允许轻微呼吸高亮，但不得导致列表重排或文本跳动。
- 必须尊重系统“减少动态效果”设置；启用时改为静态高亮。

“添加动作”固定在列表底部安全区域，保持现有菜单能力，但使用次级按钮样式。

## 其他界面

### 权限引导

权限页使用与主界面一致的图标、颜色、圆角和按钮层级：

- 明确说明辅助功能权限用途。
- “打开系统设置”为主操作。
- “重新检测”为次操作。
- 不改变现有权限请求与刷新逻辑。

### 空状态与未选择状态

脚本库为空、未选择脚本和无动作三种状态使用统一空状态组件，但文案和操作必须匹配各自上下文。不能以纯灰色系统占位页结束主要流程。

### 录制设置

录制设置 sheet 采用同一视觉 token 和按钮层级。快捷键捕获、冲突校验和保存行为保持不变。

### 提示与错误

持久化错误、快捷键注册错误继续使用系统 alert。只统一文案排版和术语，不自绘非必要弹窗。

## 动效与可访问性

动效只用于表达状态变化：

- 侧边栏选择切换。
- 录制状态。
- 回放当前动作。
- 按钮从开始切换为停止。

不添加循环装饰动画。系统启用“减少动态效果”时，所有非必要动画变为无动画或静态状态变化。

所有交互元素必须具备：

- 清晰的 accessibility label。
- 必要时提供 help/tooltip。
- 可辨认的键盘焦点。
- 不仅依靠颜色传达状态。
- 浅色与深色模式下符合可读性要求。

## 实现边界

新增集中式视觉 token，统一管理：

- 语义颜色。
- 间距。
- 圆角。
- 卡片表面。
- 状态强调。
- 动画时长与减少动态效果分支。

组件按职责拆分为独立 SwiftUI 单元：

- 品牌侧边栏与脚本行。
- 脚本标题和并列主操作区。
- 参数条。
- 动作卡片。
- 统一空状态。

不进行与视觉刷新无关的 AppState、录制引擎、回放引擎或存储重构。所有 Swift 文件继续保持少于 800 行。

## 图标与打包流程

仓库保存一份可维护的图标源资产，并生成 macOS 标准 iconset 所需尺寸：

- 16×16 与 16×16@2x。
- 32×32 与 32×32@2x。
- 128×128 与 128×128@2x。
- 256×256 与 256×256@2x。
- 512×512 与 512×512@2x。

构建流程生成或复制 `Clicker.icns` 到 `Clicker.app/Contents/Resources`，并在 `Info.plist` 设置对应图标字段。构建必须继续使用现有本地 ad-hoc 签名流程，不修改签名身份。

## 测试策略

严格执行 RED、GREEN、REFACTOR。自动测试不得真实切换应用、修改 TCC 或投递真实键鼠输入。

优先覆盖：

- 图标资源包含所需尺寸。
- 构建后的 bundle 包含 `.icns`。
- `Info.plist` 声明正确图标资源。
- 录制与回放位于同一主操作组件并拥有匹配的可访问性层级。
- 录制、倒计时、回放和空闲阶段显示正确操作与停止文案。
- 动作卡片活动状态不改变业务数据。
- 减少动态效果时使用静态状态反馈。
- 浅色与深色语义颜色均可解析并保持必要对比。
- 权限页、空状态和录制设置保留现有操作行为。

最终自动验证包括：

- 完整 `swift test`。
- Debug 与 Release 构建。
- 所有 Swift 文件少于 800 行。
- 图标尺寸与 iconset 校验。
- bundle plist 校验。
- `codesign --verify --deep --strict`。
- `git diff --check` 与 Git 状态证据。

最终人工验收包括：

- Finder、Dock、应用切换器中显示正式图标。
- 浅色与深色模式下检查所有页面。
- 常用窗口尺寸和最小窗口尺寸。
- 空脚本库、未选择脚本和长脚本滚动。
- 录制、倒计时、回放和停止状态。
- 权限引导与录制设置 sheet。

## 工程约束

- Swift 5.9、SwiftUI、AppKit，macOS 14+。
- 不引入第三方依赖或第三方字体。
- 所有 Swift 文件少于 800 行。
- 不修改 TCC、`.netrc` 或 Git identity。
- 不执行远程 Git 操作。
- `.omc/` 与 `docs/superpowers/clicker-handoff.md` 保持未跟踪。
- 测试不得向系统投递真实键鼠输入或真实切换应用。
- 精确暂存任务文件并使用 Conventional Commits。
